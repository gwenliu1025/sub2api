# Gemini 池模式 429 本地限流修复设计

## 目标

修复 Gemini 兼容层绕过现有 `pool_mode` 配置、直接写入账号级限流时间的问题。账号启用池模式且未启用自定义错误码策略时，上游 `429` 不再调用 `SetRateLimited`，账号继续参与调度。

## 边界

- 复用现有 `credentials.pool_mode`，不新增配置、数据库字段、前端开关或定时任务。
- 只修改 Gemini 兼容层的 `429` 处理；其他平台和非池模式账号保持原行为。
- 若管理员启用了自定义错误码策略，继续遵循该策略，不被池模式默认行为覆盖。
- 不隐藏 MaxAPI 的真实 `429/403`，也不增加现有池模式重试次数。

## 测试与生产验收

- 回归测试证明：池模式账号收到 Gemini `429` 时不写本地限流；普通账号仍写入限流。
- 本地完成定向测试、服务包测试和构建。
- 生产变更前备份当前镜像、Compose/环境文件及账号 `3250` 的非敏感状态。
- 只重建 `sub2api`，随后清除账号 `3250` 的历史限流字段并确认其为 `active/schedulable`。
- 检查本机与公网健康状态，并比较所有无关容器启动时间。

## 回滚

恢复变更前镜像并只重建 `sub2api`；账号数据没有结构迁移。
